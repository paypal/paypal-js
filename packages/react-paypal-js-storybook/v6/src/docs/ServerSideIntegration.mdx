# Server-Side Integration

The buttons in this Storybook render in the browser, but a real integration needs
a server for anything sensitive: it holds your **client secret**, owns **pricing**,
and creates/captures **orders**. The browser never sees the secret and never
decides the amount.

Both official samples talk to the **same Node/Express backend**. This page distills
its API contract; the full request/response reference lives in the
[server README](https://github.com/paypal-examples/v6-web-sdk-sample-integration/blob/main/server/node/README.md).

## Authentication: token vs. client ID

The SDK supports two browser-safe auth options:

- **Client token** — short-lived; unlocks **every** SDK feature. Fetch it per
  session from `browser-safe-client-token`.
- **Client ID** — a static public identifier; works with a **limited** feature
  set. Simpler, but not sufficient for every method.

When in doubt, use the **client token**. See PayPal's
[Authentication docs](https://developer.paypal.com/api/rest/authentication/).

## The create → approve → capture flow

Three steps, with the two API calls on your server:

1. **Create** — the button's `createOrder` calls your `create-order` endpoint,
   which calls PayPal and returns an `orderId`.
2. **Approve** — the buyer approves in the PayPal or wallet UI (handled by the SDK).
3. **Capture** — the button's `onApprove` receives the `orderId` and calls your
   `capture` endpoint, which finalizes the payment and returns
   `status: "COMPLETED"`.

The client only forwards the `orderId` it receives back to your capture endpoint —
it never creates or captures directly.
